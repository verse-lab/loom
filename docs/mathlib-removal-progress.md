The first implementation increment reduces imports and prepares standalone
control foundations. Full mathlib removal remains in progress.

Implemented changes:

- Added a repeatable compiled-dependency audit in `scripts/AuditDependencies.lean`.
- Added a Lake test driver with extraction regression fixtures. The initial
  result-order, duplicate, logging, and branching checks passed on the original
  implementation before the trim. Further checks cover retained join-point
  lets, divergence logs, and helper behavior.
- Moved the `FinEnum` candidate instance into `LoomMathlib.Candidates`, in a
  separate local integration package. Its tests check automatic synthesis,
  predicate filtering, empty results, and enumeration order.
- Removed unused tree/function imports and the explicit mathlib tactic/helper
  imports; replaced all 41 `introv` uses with core introductions.
- Added a standalone list congruence lemma and used explicit monoid laws in
  proofs that had depended on transitively imported instances.
- Replaced extraction's target and application-argument helpers with Lean APIs,
  preserving target lets and providing an explicit out-of-bounds contract.
- Added namespaced `Loom.ContT`, `Loom.WriterT`, and `Loom.LogMonoid`, their laws,
  and explicit mathlib conversions. These compile without external packages
  and coexist with mathlib. They are not yet wired into the WP semantics.
- Added a native-consumer fixture and CI checks for the standalone
  foundations and optional adapter.

The compiled audit of `import Loom` went from 440 to 222 mathlib modules.
Direct references to mathlib declarations went from 229 to 224. This illustrates
that the trim mostly removes transitive imports: the order-theory work remains.
The root manifest still requires mathlib and its packages. These figures are
import counts, not build-time measurements.

Consumers supplying `Candidates` directly retain that interface. Consumers
relying on automatic `FinEnum` candidates must add the local integration package
and import `LoomMathlib.Candidates`; see its README. The integration's manifest
is generated by Lake and pins the same mathlib commit as the root checkout.

The next implementation increment is the namespaced order hierarchy, generic
models, and early mathlib conversion checks. After that come the algebra and
WP/WLP proof ports, use of the new control types in semantics, and the Veil
migration. Full Veil validation, Git distribution of the adapter, fresh
mathlib-free builds of the entire library, and performance comparison remain
outstanding. The audit and focused regression tests are a starting baseline;
they do not constitute completion of every baseline task in the full plan.

Validation commands for this increment:

```bash
lake build
lake build Loom:static
lake test
python3 scripts/check_foundations.py
lake -d integrations/mathlib test
lake -d tests/native exe smoke
lake env lean --run scripts/AuditDependencies.lean /tmp/loom-audit
```

`check_foundations.py` replaces `LEAN_PATH` with only this checkout's build
directory. Thus the control and metaprogramming tests cannot obtain imports
from cached external packages. The native fixture builds an executable and
executes an extracted computation. A separate attempt with
`precompileModules := true` was stopped because Lake started building mathlib's
entire shared library. That configuration remains to be validated after the
standalone semantics port; it is not enabled in this increment's CI.
